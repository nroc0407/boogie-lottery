# 부기 추첨자

디시인사이드 나눔 게시글 주소 하나로 댓글 참가자를 모으고, 공개 갤로그에서 해당 갤러리의 글·댓글 활동을 확인한 뒤 당첨자를 자동 추첨합니다. 갤로그 글·댓글 목록 중 하나라도 비공개면 참가자를 제외합니다. 평가기간과 활동 기준을 직접 설정할 수 있으며, 최소 글·댓글 모드와 글댓합 모드는 독립적으로 작동합니다. 갤스코프의 작성자 식별 방식을 사용합니다. AI 기능은 없습니다.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fnroc0407%2Fboogie-lottery)

## 사용 방법

1. 일반·마이너·미니 갤러리의 게시글 주소를 붙여 넣습니다.
2. 당첨 인원, 평가기간, 활동 기준 모드를 설정합니다. 기본값은 1명, 최근 6개월, 최소 글·댓글 모드의 글 3개·댓글 0개입니다.
   - 기간: 1~24개월 또는 1~730일. 시작일 한국 시각 0시부터 추첨 시작 시점까지 평가합니다. 일 단위는 오늘을 포함한 날짜 수입니다.
   - 최소 글·댓글 모드: 각각 0~1,000개. 활성화한 두 기준을 모두 충족해야 합니다. 0개로 설정한 항목은 건수 기준을 적용하지 않습니다. 합계 기준은 적용하지 않습니다.
   - 글댓합 모드: 합계 0~2,000개. 작성글 수 + 작성댓글 수의 합계만 판정하며, 개별 최소 글·댓글 설정은 적용하지 않습니다. 예: 합계 10개일 때 글 3개 + 댓글 7개 또는 글 10개로 통과할 수 있습니다.
   - 모드를 바꿔도 입력값은 보존되지만, 선택한 모드의 값만 평가합니다. 기준을 모두 0개로 두어도 갤로그 글·댓글 목록의 공개 여부는 확인합니다.
3. 필요하면 참여 댓글 키워드, 대댓글 포함, 글쓴이 제외 여부를 조정합니다. 연결할 갤로그가 없는 유동은 제외합니다.
4. 추첨 시작을 누릅니다. 중앙 진행 창에서 댓글 수집 → 활동 확인 → 추첨의 단계, 경과 시간, 조회 페이지와 처리 내역을 확인할 수 있습니다. 로그는 현재 탭에 최근 120개까지 보관합니다.
5. 당첨자 이름을 눌러 참여 댓글을 확인합니다. 결과를 복사하거나 참가자 판정과 당첨 표시가 담긴 CSV를 저장할 수 있습니다.

화면은 검은 배경과 녹색 글씨의 중앙 콘솔로 구성돼 있습니다. 키워드·대댓글·글쓴이 옵션은 추가 설정, 참가자별 갤로그 상태와 판정은 참가자 목록을 펼쳐 확인합니다.

## 참가자와 활동 판정

- 로그인 계정은 공개 UID로 중복 댓글을 1명으로 묶습니다. 닉네임이 바뀌어도 UID가 같으면 같은 참가자로 처리하며, 같은 닉네임을 쓴 다른 계정은 분리합니다.
- 삭제·시스템 댓글은 참가자에서 제외합니다. 기본값은 대댓글 포함, 게시글 작성자 제외입니다. 연결할 갤로그가 없는 유동·미식별 참가자도 제외합니다.
- 갤로그의 글 목록(`/posting`)과 댓글 목록(`/comment`)을 모두 확인합니다. 명시적인 비공개 표시가 하나라도 있으면 **갤로그 비공개로 제외**합니다. 공개 목록에 활동이 없다는 표시는 비공개와 구분합니다. HTTP 오류·시간 초과·알 수 없는 응답 형식을 비공개로 단정하지 않고 보류합니다.
- 글·댓글 수는 공개 갤로그의 개별 기록을 날짜순으로 조회해 셉니다. 기록 링크에서 추출한 **갤러리 ID와 갤러리 종류가 추첨글 주소와 모두 일치**해야 합니다. 다른 갤러리 활동과 갤로그 전체 글·댓글 합계는 판정에 쓰지 않습니다. 해당 갤러리의 기록만 활동 응답에 담습니다.
- 선택한 평가기간의 기록만 셉니다. 나눔 게시글 자체와 그 글에 남긴 댓글은 제외합니다. 오래된 게시글에 평가기간 중 남긴 댓글은 갤로그에 공개돼 있으면 포함합니다. 대댓글 포함 설정·참여 키워드는 참가자 모집에만 적용합니다. 갤로그 날짜는 일 단위이므로 평가 시작일과 종료일을 날짜 기준으로 포함하며, 그 날짜 안의 세부 시각은 구분할 수 없습니다. CSV의 날짜 정밀도는 `day`입니다.
- 현재 공개된 갤로그 내역이 기준이며 과거 수집 DB는 사용하지 않습니다. 원 게시글이 삭제됐더라도 갤로그에 기록이 남아 있다면 집계에 포함될 수 있습니다.
- 최소 글·댓글 모드는 활성화한 개별 기준을 모두 충족해야 합니다. 글댓합 모드는 확인된 글 + 댓글 수의 합계만 평가합니다. 모든 참가자에게 공개 여부 확인이 선행되며, 기준을 충족한 뒤에는 더 오래된 페이지를 조회하지 않을 수 있습니다. 표시된 활동 수는 확인한 하한값입니다.
- 기준 미달·활동 없음은 필요한 목록의 기간 경계 또는 끝을 확인한 뒤 판정합니다. 합계 미달은 글과 댓글 양쪽의 범위 확인이 필요합니다. 날짜·링크·페이지 정보의 오류, 중단, 참가자별 글 또는 댓글 목록의 2,000페이지 제한으로 필요한 기준을 확정할 수 없으면 보류합니다. 이미 확인한 공개 기록으로 기준을 충족하면 통과할 수 있습니다. **미확인 참가자가 남으면 자동 추첨을 진행하지 않습니다.**
- 참가자 표에는 공개·비공개·미확인 상태와 제외 사유를 표시합니다. CSV에는 갤로그 상태, 대상 갤러리 ID·종류, 글·댓글 범위 확인 여부를 추가합니다.
- 댓글은 최대 100페이지까지 수집합니다. 페이지가 더 남으면 전체 참가자 확인 없이 추첨하지 않습니다.

## 추첨

통과 참가자에게는 각각 같은 확률을 줍니다. 브라우저의 Web Crypto 난수와 편향 없는 정수 추출로, 당첨자끼리 중복되지 않게 선정합니다. 댓글을 더 남기거나 글을 더 많이 써도 가중치를 주지 않습니다. 후보 수보다 당첨 인원이 많으면 추첨을 보류합니다. 다시 추첨은 같은 후보 명단에서 새 난수로 뽑는 명시적인 버튼입니다.

## 실행 및 배포

로컬에서는 이 폴더에서 `node scripts/dev-server.mjs` 또는 `npm run dev`를 실행한 뒤 `http://127.0.0.1:4387`을 엽니다. `PORT`로 로컬 포트를 변경할 수 있습니다. 로컬 서버는 배포에 사용하는 API 함수를 호출합니다.

독립 공개 저장소는 [nroc0407/boogie-lottery](https://github.com/nroc0407/boogie-lottery)입니다. Vercel에서 이 저장소를 Import하고 Root Directory는 저장소 루트(`.`), Framework Preset은 **Other**로 선택합니다. Node.js 24, 정적 출력 `public`, 설치·검사 명령은 저장소 설정 파일에 지정돼 있어 별도 환경 변수가 필요하지 않습니다. `api/comments.js`, `api/pages.js`, `api/comment-activity.js`가 서버 함수로 함께 배포됩니다.

위 Deploy with Vercel 버튼은 저장소를 복사해 새 프로젝트를 만드는 템플릿 배포 방식입니다. 현재 저장소의 변경을 자동 배포하려면 [Vercel New Project](https://vercel.com/new)에서 이 저장소를 직접 Import합니다.

개발용 원본을 다른 저장소의 `boogie-lottery/` 하위 폴더에서 배포하는 경우에만 Root Directory를 `boogie-lottery`로 지정합니다.

Vercel에 저장소를 연결한 뒤에는 Vercel Git 연동으로 배포가 이루어집니다. 이 저장소에 Vercel 토큰을 등록하는 별도 배포 워크플로는 필요하지 않습니다. 배포 때 `npm run check`가 설정과 JavaScript 문법을 검사합니다.

GitHub Actions 자동 검사는 [docs/ci-workflow.yml.example](docs/ci-workflow.yml.example)에 준비돼 있습니다. 현재 업로드 인증에는 `workflow` 권한이 없어 활성화하지 않았습니다. 워크플로 쓰기 권한이 있는 인증 또는 GitHub 웹 편집기로 이 파일을 `.github/workflows/ci.yml`에 추가하면 push·pull request마다 설치·배포 설정 검사와 7개 테스트를 실행합니다.

## 데이터 처리

원 계정 ID와 IP는 서버 함수에서 이번 실행에만 쓰는 HMAC 식별자로 바꾸고 응답에서 제외합니다. 댓글 내용·표시명·댓글 번호·활동 건수·당첨 결과는 브라우저 탭 메모리에만 남습니다. 쿠폰 발송, 댓글 작성, 계정 로그인, 서버 DB 저장은 하지 않습니다. 배포 제공자는 플랫폼 표준 요청 메타데이터를 처리할 수 있습니다.

처음에는 갤로그 글·댓글 목록 각 1페이지로 공개 여부를 확인하고, 이후 필요한 목록을 한 번에 최대 3페이지씩 순차 조회합니다. API 요청 사이에는 최소 1.1초 대기합니다. 활동 조회는 참여 댓글 페이지에서 원 UID를 서버 안에서 다시 확인하므로 브라우저에 원 UID나 갤로그 주소를 전달하지 않습니다. 다른 갤러리 기록은 서버에서 제외하며 응답에는 일치하는 기록, 범위 확인 여부와 중복 페이지 감지용 해시만 담습니다. 인스턴스 메모리의 분당 제한은 전역 영속 제한이 아니므로 공개 대규모 서비스에는 별도 요청 제한이 필요합니다.

## 확인

`node --test tests/lottery.test.mjs`로 URL 제한, 월말 6개월 계산, 댓글 중복·동명 계정 처리, 목록과 댓글 UID 연결, 미확인 보류, 중복 없는 추첨, 댓글 페이지 이동을 확인합니다. `scripts/verify-connection.mjs`는 Playwright를 사용해 예시 글의 실제 댓글 수집부터 활동 조회, 당첨자 표시, CSV 다운로드까지 확인합니다. 검증 산출물은 Git에서 제외한 `artifacts/`에 둡니다.
