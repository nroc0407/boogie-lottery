# 부기 추첨자

디시인사이드 나눔 게시글 주소 하나로 댓글 참가자를 모으고, 공개 갤로그에서 해당 갤러리의 글·댓글 활동을 확인합니다. 포함·불포함 명단을 검토한 뒤 포함 대상만 추첨합니다. 갤로그 글·댓글 목록 중 한쪽만 비공개면 공개된 목록만으로 판정하고(비공개 쪽은 0개), 두 목록이 모두 비공개면 제외합니다. 운영자는 자동 판정과 관계없이 모든 참가자를 사유와 함께 수동으로 포함·불포함할 수 있습니다. 평가기간과 활동 기준을 직접 설정할 수 있으며, 최소 글·댓글 모드와 글댓합 모드는 독립적으로 작동합니다. 갤스코프의 작성자 식별 방식을 사용합니다. AI 기능은 없습니다.

## 사용 방법

1. 일반·마이너·미니 갤러리의 게시글 주소를 붙여 넣습니다. PC 주소, 모바일 주소(`m.dcinside.com/board/갤러리/글번호`), 단축 공유 주소(`gall.dcinside.com/갤러리/글번호`)를 지원합니다. 같은 글을 가리키는 디시의 이동 안내를 확인해 실제 갤러리 종류와 정식 주소를 사용합니다.
2. 당첨 인원, 평가기간, 활동 기준 모드를 설정합니다. 기본값은 1명, 기간 제한 없음, 최소 글·댓글 모드의 글 3개·댓글 0개입니다.
   - 기간: 기본값인 **기간 제한 없음**은 참가자 확인을 시작한 시점까지 공개된 전체 기간의 활동을 평가합니다. 기간을 정하려면 ‘개월’을 선택하고 최근 1~24개월을 입력합니다. 월 단위는 시작일 한국 시각 0시부터 평가합니다. 일 단위 설정은 제공하지 않습니다.
   - 최소 글·댓글 모드: 각각 0~1,000개. 활성화한 두 기준을 모두 충족해야 합니다. 0개로 설정한 항목은 건수 기준을 적용하지 않습니다. 합계 기준은 적용하지 않습니다.
   - 글댓합 모드: 합계 0~2,000개. 작성글 수 + 작성댓글 수의 합계만 판정하며, 개별 최소 글·댓글 설정은 적용하지 않습니다. 예: 합계 10개일 때 글 3개 + 댓글 7개 또는 글 10개로 통과할 수 있습니다.
   - 모드를 바꿔도 입력값은 보존되지만, 선택한 모드의 값만 평가합니다. 기준을 모두 0개로 두어도 갤로그 글·댓글 목록의 공개 여부는 확인합니다.
3. 필요하면 참여 댓글 키워드, 대댓글 포함, 글쓴이 제외 여부를 조정합니다. 연결할 갤로그가 없는 유동은 제외합니다.
4. **참가자 확인**을 누릅니다. 댓글 수집 → 활동 확인 → 명단 확인 순서로 진행하며 아직 추첨하지 않습니다. 닉네임 뒤에 계정의 공개 식별코드를 표시해 같은 ‘ㅇㅇ’도 구분합니다. 초록색 포함·빨간색 불포함·노란색 미확인 명단에서 판정 사유를 확인합니다. 자동 판정(통과·기준 미달·비공개·미확인·게시글 작성자·갤로그 없음 등)과 관계없이 모든 참가자를 **포함**·**불포함**으로 직접 정할 수 있습니다. 버튼을 누르면 참가자 아래에 짧은 사유 입력 칸(선택, 100자)이 열리고 Enter 또는 확인으로 적용하며, Esc·취소로 닫습니다. 수동 판정은 ‘수동 포함 · 원래: 비공개 · 사유: …’처럼 원래 자동 판정과 함께 표시되고 자동 판정 사유도 한 줄 더 보여 주며, **자동**을 누르면 자동 판정으로 되돌립니다. 수동으로 포함·불포함한 미확인 참가자는 추첨을 막지 않습니다. ‘통과자 전체 불포함’은 통과자 전원을 사유 ‘통과자 전체 불포함’으로 수동 불포함하고, ‘통과자 전체 포함’은 통과자의 수동 불포함을 모두 되돌립니다. **포함 대상 추첨하기**를 눌러야 추첨합니다. 당첨 인원은 명단 확인 후에도 바꿀 수 있으며 다른 조건을 바꾸면 다시 확인해야 합니다. 추첨 후 명단은 고정됩니다. 로그는 현재 탭에 최근 120개까지 보관합니다.
   - 일시적인 접속 오류(네트워크 끊김, 서버 502·503·504, 읽을 수 없는 응답)는 간격을 늘려 가며 최대 3번까지 다시 요청하고, 참가자별 갤로그 오류도 2번까지 다시 확인한 뒤 미확인으로 남깁니다. 요청 제한(429)을 받으면 서버가 알려 준 시간만큼 기다린 뒤 이어서 확인합니다. 디시인사이드가 요청을 제한하면 한 번 기다렸다가 다시 시도하고, 계속 제한되면 확인을 멈춥니다.
   - 미확인 참가자가 남거나 확인이 중간에 멈추면 **미확인 n명만 다시 확인**을 누릅니다. 같은 평가 시각·설정으로 자동 판정이 미확인인 참가자만 다시 확인하며 이미 확인된 결과는 유지합니다. 수동으로 정한 미확인 참가자도 다시 확인하지만 수동 판정은 바꾸지 않고, 표시되는 자동 판정(‘원래: …’)만 새 결과로 갱신합니다. 설정을 바꿨다면 참가자 확인을 새로 실행해야 합니다.
5. 당첨자 이름을 눌러 참여 댓글을 확인합니다. 결과를 복사하거나 참가자 판정과 당첨 표시가 담긴 CSV를 저장할 수 있습니다.
   - **PNG 저장**: 당첨자, 원문 주소, 추첨 조건·시각·번호·회차, ‘수동 포함 n명 · 수동 불포함 n명’과 명단 해시(SHA-256)가 담긴 결과 이미지를 받습니다. 수동 포함된 당첨자와 비공개 목록은 당첨자 카드에 표시합니다.
   - **JSON 저장**(`schemaVersion: 3`): 설정, 공개 식별코드, 글·댓글 목록별 공개 상태(`listVisibility`), 자동 판정(`automaticStatus`·`automaticReason`·`automaticVerdict`)과 수동 판정(`manualOverride`: 결정·사유·시각·결정 당시 자동 판정, 전체 목록은 `manualOverrides`), 명단 해시(`rosterHash`), 이번 실행의 추첨·재추첨 내역(사유 포함), 이 탭의 전체 추첨 기록(`drawLog`)과 최근 120개 처리 로그를 기록 파일로 받습니다. 명단 확인·중단·보류 후에도 저장할 수 있으며 IP·세션 키·댓글 본문은 담지 않습니다.
   - **ZIP 저장**: 같은 추첨 결과의 PNG와 JSON을 한 파일로 받습니다. PNG와 ZIP은 추첨 완료 후 사용할 수 있습니다.
   - **결과 복사**에도 수동 포함·불포함 인원과 참가자별 수동 판정(원래 판정·사유), 명단 해시와 확인 방법이 들어갑니다.
   - **CSV 저장**에는 `post_list_visibility`·`comment_list_visibility`, `automatic_verdict`·`automatic_reason`, `manual_decision`·`manual_reason`·`manual_decided_at`·`manual_verdict_at_decision`·`manual_included`·`manual_excluded` 열이 함께 들어갑니다.
   - 내보낸 파일은 기기에 저장합니다. 서버 저장이나 공유 주소는 생성하지 않습니다. 추첨 후 참가자 확인을 새로 시작하면 확인 창을 띄우고, 현재 명단과 결과는 초기화하지만 이 탭의 추첨 기록은 남깁니다. 탭을 닫거나 새로 고치면 추첨 기록도 사라집니다.

화면은 검은 배경과 녹색 글씨의 중앙 콘솔로 구성돼 있습니다. ‘추첨 설정’ 옆 ‘사용법’을 누르면 활동 내역 공개 조건과 설정·추첨·결과 저장 방법을 확인할 수 있습니다. 키워드·대댓글·글쓴이 옵션은 추가 설정, 참가자별 갤로그 상태와 판정은 참가자 목록을 펼쳐 확인합니다.

참가자 미리보기의 **포함·불포함·미확인 제목**을 눌러 각 명단을 펼치거나 접을 수 있습니다. 불포함은 비공개·목록 비공개로 기준 미달·활동 기준 미달·게시글 작성자·갤로그 없음·수동 불포함 등의 사유별 인원수를 먼저 보여주며, 사유 제목을 누르면 해당 참가자와 상세 사유가 펼쳐집니다. 접은 상태는 검사 진행이나 수동 선택으로 명단이 갱신되어도 유지됩니다. 닉네임·식별코드를 검색하면 일치하는 불포함 사유 묶음이 펼쳐지고 검색을 지우면 원래 상태로 돌아갑니다.

## 참가자와 활동 판정

- 로그인 계정은 공개 UID로 중복 댓글을 1명으로 묶습니다. 닉네임이 바뀌어도 UID가 같으면 같은 참가자로 처리하며, 같은 닉네임을 쓴 다른 계정은 분리합니다. 공개 식별코드를 닉네임 옆에 표시하고 검색·결과 복사·PNG·JSON·CSV에 함께 담습니다.
- 삭제·시스템 댓글은 참가자에서 제외합니다. 기본값은 대댓글 포함, 게시글 작성자 제외입니다. 연결할 갤로그가 없는 유동·미식별 참가자도 제외합니다.
- 갤로그의 글 목록(`/posting`)과 댓글 목록(`/comment`)을 모두 확인하고 목록마다 공개·일부공개·비공개를 기록합니다. **한쪽 목록만 비공개면** 다른 목록을 평소처럼 모든 필요한 페이지까지 읽고 비공개 쪽은 0개로 셉니다. 최소 글·댓글 모드는 공개된 쪽 건수로 기준을 판정하므로, 예를 들어 글 3개·댓글 0개 기준에서 댓글 목록만 비공개면 글 목록만으로 통과할 수 있고(‘댓글 목록 비공개 — 글 목록만으로 판정’), 비공개 쪽 기준이 1개 이상이면 ‘글 목록 비공개로 작성글 기준 미달 (0/3개)’처럼 비공개 사유를 밝혀 기준 미달로 제외합니다. 글댓합 모드는 공개된 목록의 건수만 더합니다. **글·댓글 목록이 모두 비공개면 갤로그 비공개(글·댓글 모두)로 제외**합니다. 비공개 표시는 목록 앞의 공개 상태 라벨(공백·`&nbsp;`·안쪽 태그 무시)이나, 기록 행이 없는 페이지의 비공개 안내 문구로 인식하며 이런 페이지는 차단 화면 검사나 미확인으로 넘기지 않습니다. **일부공개**는 미확인이 아니라 공개된 기록을 읽을 수 있는 상태로 처리하며 화면과 기록에 `partial` 상태를 보존합니다. 대상 갤러리의 보이는 기록만 집계하므로 다른 갤러리만 공개했거나 대상 기록을 숨겼다면 해당 활동 기준을 충족하지 못할 수 있습니다. 공개 목록에 활동이 없다는 표시는 비공개와 구분합니다. HTTP 오류·시간 초과·알 수 없는 응답 형식을 비공개로 단정하지 않고 보류합니다.
- 글·댓글 수는 공개 갤로그의 개별 기록을 날짜순으로 조회해 셉니다. 기록 링크에서 추출한 **갤러리 ID와 갤러리 종류가 추첨글 주소와 모두 일치**해야 합니다. 다른 갤러리 활동과 갤로그 전체 글·댓글 합계는 판정에 쓰지 않습니다. 해당 갤러리의 기록만 활동 응답에 담습니다.
- 선택한 평가기간의 기록만 셉니다. 나눔 게시글 자체와 그 글에 남긴 댓글은 제외합니다. 오래된 게시글에 평가기간 중 남긴 댓글은 갤로그에 공개돼 있으면 포함합니다. 대댓글 포함 설정·참여 키워드는 참가자 모집에만 적용합니다. 갤로그 날짜는 일 단위이므로 평가 시작일과 종료일을 날짜 기준으로 포함하며, 그 날짜 안의 세부 시각은 구분할 수 없습니다. CSV의 날짜 정밀도는 `day`입니다.
- 현재 공개된 갤로그 내역이 기준이며 과거 수집 DB는 사용하지 않습니다. 원 게시글이 삭제됐더라도 갤로그에 기록이 남아 있다면 집계에 포함될 수 있습니다.
- 최소 글·댓글 모드는 활성화한 개별 기준을 모두 충족해야 합니다. 글댓합 모드는 확인된 글 + 댓글 수의 합계만 평가합니다. 모든 참가자에게 공개 여부 확인이 선행되며, 기준을 충족한 뒤에는 더 오래된 페이지를 조회하지 않을 수 있습니다. 표시된 활동 수는 확인한 하한값입니다.
- 참여 댓글은 최신순 페이지에서 다시 찾습니다. 새 댓글이 달려 기억한 페이지에서 밀려났으면 인접 페이지(+1, −1, +2, −2) 순서로 찾은 뒤에도 없을 때만 보류합니다.
- 기준 미달·활동 없음은 필요한 목록의 기간 경계 또는 끝을 확인한 뒤 판정합니다. 합계 미달은 글과 댓글 양쪽의 범위 확인이 필요합니다. 날짜·링크·페이지 정보의 오류, 중단, 참가자별 글 또는 댓글 목록의 2,000페이지 제한으로 필요한 기준을 확정할 수 없으면 보류합니다. 이미 확인한 공개 기록으로 기준을 충족하면 통과할 수 있습니다. **미확인 참가자가 남으면 자동 추첨을 진행하지 않습니다.** 미확인 참가자를 수동으로 포함·불포함하면 확인된 것으로 보고 추첨을 막지 않습니다.
- 참가자 표에는 공개·비공개·미확인 상태(한쪽만 비공개면 ‘글 공개 · 댓글 비공개’), 비공개 목록의 ‘비공개 (0)’, 판정 사유와 수동 판정을 표시합니다. CSV에는 갤로그 상태, 목록별 공개 상태, 대상 갤러리 ID·종류, 글·댓글 범위 확인 여부를 추가합니다.
- 댓글은 최대 100페이지까지 수집합니다. 페이지가 더 남으면 전체 참가자 확인 없이 추첨하지 않습니다.

## 추첨

통과 참가자에게는 각각 같은 확률을 줍니다. 브라우저의 Web Crypto 난수와 편향 없는 정수 추출로, 당첨자끼리 중복되지 않게 선정합니다. 댓글을 더 남기거나 글을 더 많이 써도 가중치를 주지 않습니다. 후보 수보다 당첨 인원이 많으면 추첨을 보류합니다. 다시 추첨은 같은 후보 명단에서 새 난수로 뽑는 명시적인 버튼이며, 누를 때마다 사유(선택)를 묻고 회차·시각·당첨자·사유를 추첨 기록에 남깁니다. 사유 입력 창에서 취소하면 재추첨하지 않습니다.

### 명단 해시로 확인하기

명단 확인이 끝나면 **명단 지문**(SHA-256 앞 12자리)을 표시하고, 추첨 후에는 당첨자 아래에 전체 해시를 표시합니다. 해시는 다음 값을 키 순서가 고정된 JSON 한 줄(`rosterHash.canonical`)로 만든 뒤 UTF-8 그대로 SHA-256으로 계산합니다.

- 게시글 정식 주소, 평가기간(단위·개월 수·시작·끝 시각), 선택한 모드와 그 모드의 기준값, 당첨 인원
- 포함된 참가자의 `[공개 식별코드, 참여 댓글 번호, 글 목록 공개 상태, 댓글 목록 공개 상태]` 목록을 코드포인트 순으로 정렬한 값(공개 상태는 `public`·`partial`·`private`, 확인하지 않았으면 `not-checked`)
- 수동 판정한 모든 참가자(포함·불포함)의 `[공개 식별코드, 참여 댓글 번호, 결정(include·exclude), 현재 자동 판정, 결정 당시 자동 판정, 사유, 결정 시각]` 목록을 같은 순서로 정렬한 값(`overrides`)

같은 명단·목록 공개 상태·수동 판정과 설정이면 수집·선택 순서와 관계없이 해시가 같고, 한 명이나 수동 판정 하나(사유·시각 포함)라도 바뀌면 달라집니다. canonical 형식은 `version: 2`입니다. 추첨 기록(`drawLog`)의 각 항목은 그때 쓴 명단 해시(`rosterSha256`)와 수동 포함·불포함 인원을 함께 남깁니다. 추첨 전에 명단 지문을 공지해 두면 이후 명단을 바꾸지 않았음을 보일 수 있습니다. 확인하려면 JSON의 `participants`에서 `included: true`인 참가자의 `[identityCode, entryCommentId, listVisibility.post, listVisibility.comment]`가 `canonical`의 `roster`와, `manualOverride`가 있는 참가자의 `[identityCode, entryCommentId, decision, automaticVerdict, automaticAtDecision, reason, decidedAt]`이 `overrides`와 같은지 본 뒤, `canonical` 문자열의 SHA-256을 계산해 `sha256`과 비교합니다(예: `node -e 'const r=require("./기록.json");console.log(require("crypto").createHash("sha256").update(r.rosterHash.canonical).digest("hex"))'`). 해시는 명단 고정을 증명할 뿐, 난수 자체를 사후 검증하지는 않습니다.

## 실행 및 배포

로컬에서는 이 폴더에서 `node scripts/dev-server.mjs` 또는 `npm run dev`를 실행한 뒤 `http://127.0.0.1:4387`을 엽니다. `PORT`로 로컬 포트를 변경할 수 있습니다. 로컬 서버는 배포에 사용하는 API 함수를 호출합니다.

독립 공개 저장소는 [nroc0407/boogie-lottery](https://github.com/nroc0407/boogie-lottery)입니다. Vercel에서 이 저장소를 Import하고 Root Directory는 저장소 루트(`.`), Framework Preset은 **Other**로 선택합니다. Node.js 24, 정적 출력 `public`, 설치·검사 명령은 저장소 설정 파일에 지정돼 있어 별도 환경 변수가 필요하지 않습니다. `api/comments.js`, `api/comment-activity.js`가 서버 함수로 함께 배포됩니다. 응답에는 `vercel.json`의 보안 헤더와 Content-Security-Policy(자체 스크립트·스타일만, data: 파비콘, 같은 출처 요청만, 프레임 금지)가 붙으며 로컬 서버도 같은 헤더를 보냅니다. 미리보기 배포의 Vercel 툴바 스크립트는 이 정책에서 차단됩니다.

위 Deploy with Vercel 버튼은 저장소를 복사해 새 프로젝트를 만드는 템플릿 배포 방식입니다. 현재 저장소의 변경을 자동 배포하려면 [Vercel New Project](https://vercel.com/new)에서 이 저장소를 직접 Import합니다.

개발용 원본을 다른 저장소의 `boogie-lottery/` 하위 폴더에서 배포하는 경우에만 Root Directory를 `boogie-lottery`로 지정합니다.

Vercel에 저장소를 연결한 뒤에는 Vercel Git 연동으로 배포가 이루어집니다. 이 저장소에 Vercel 토큰을 등록하는 별도 배포 워크플로는 필요하지 않습니다. 배포 때 `npm run check`가 설정·CSP 존재·JavaScript 문법을 검사하고 `tests/*.test.mjs` 전체를 실행하며, 테스트가 하나라도 실패하면 배포를 중단합니다. 테스트는 `fetch`를 모의해 외부 네트워크를 쓰지 않습니다.

GitHub Actions 자동 검사는 [docs/ci-workflow.yml.example](docs/ci-workflow.yml.example)에 준비돼 있습니다. 현재 업로드 인증에는 `workflow` 권한이 없어 활성화하지 않았습니다. 워크플로 쓰기 권한이 있는 인증 또는 GitHub 웹 편집기로 이 파일을 `.github/workflows/ci.yml`에 추가하면 push·pull request마다 설치와 `npm run check`(배포 설정 검사와 51개 테스트)를 실행합니다.

## 데이터 처리

계정의 공개 식별코드는 동명 참가자 구분을 위해 화면과 내보낸 파일에 표시합니다. 내부 참가자 연결에는 이번 실행에만 쓰는 HMAC 식별자를 사용하며 원 IP는 응답에서 제외합니다. 댓글 내용·표시명·공개 식별코드·댓글 번호·활동 건수·수동 판정과 사유·당첨 결과는 브라우저 탭 메모리에 두고, 사용자가 내보내기를 선택하면 기기에 저장합니다. 쿠폰 발송, 댓글 작성, 계정 로그인, 서버 DB 저장은 하지 않습니다. 배포 제공자는 플랫폼 표준 요청 메타데이터를 처리할 수 있습니다.

처음에는 갤로그 글·댓글 목록 각 1페이지로 목록별 공개 여부를 확인하며(한쪽이 비공개여도 다른 쪽 1페이지를 읽음, 요청 본문의 `listRule: "visible-only"`. 이 값이 없는 이전 클라이언트와 단일 대상 형식에는 이전 규칙대로 한쪽 비공개를 비공개로 응답), 한 번의 요청에 참가자 최대 4명을 묶어 게시글·댓글 페이지를 한 번만 읽습니다. 이후 필요한 목록을 참가자별로 한 번에 최대 3페이지씩 순차 조회합니다. API 요청 사이에는 최소 1.1초, 서버의 디시인사이드 요청 사이에는 0.3초 대기합니다. 서버 함수는 같은 인스턴스가 이어서 쓰일 때를 위해 게시글 정보를 60초, 댓글 페이지를 30초 동안 인스턴스 메모리에만 보관하며 다른 인스턴스와 공유하거나 저장하지 않습니다. 함수 제한 시간(30초)에 걸리지 않도록 20초가 지나면 새 디시인사이드 요청을 시작하지 않고 그때까지 읽은 페이지를 돌려주며(각 요청은 최대 5초, 25초 안에 끝남), 브라우저는 남은 페이지·참가자를 이어서 요청합니다. 디시인사이드가 403·429나 차단·자동 입력 방지 화면을 보내면 해당 인스턴스는 30~300초 동안 디시 요청을 멈추고 대기 시간을 알려 줍니다. 활동 조회는 브라우저가 전달한 식별코드를 신뢰하지 않고 참여 댓글의 작성자를 서버 안에서 다시 확인합니다. 다른 갤러리 기록은 서버에서 제외하며 응답에는 일치하는 기록, 범위 확인 여부와 중복 페이지 감지용 해시만 담습니다. 인스턴스 메모리의 분당 제한(IP당 80회, 초과 시 남은 초를 `Retry-After`로 안내)은 전역 영속 제한이 아니므로 공개 대규모 서비스에는 별도 요청 제한이 필요합니다. API는 `Origin`(없으면 `Referer`)이 배포 주소와 다르거나 `Sec-Fetch-Site: cross-site`인 요청을 403으로 거절해 다른 사이트가 이 배포를 디시 조회 경유지로 쓰지 못하게 합니다. 두 헤더가 모두 없는 비브라우저 요청은 분당 제한만 적용합니다. 서버 로그에는 요청마다 엔드포인트·상태·소요 시간·디시 요청 수와 마지막 상태·캐시 사용·오류 종류만 JSON 한 줄로 남기며 UID·IP·닉네임·주소·댓글은 남기지 않습니다.

## 확인
